# Adobe Acrobat DC 安装失败：错误 1714 / 1612 与旧版 MSI 残留修复

> **案例状态：已解决（2026-10-27）**  
> **系统：Windows（具体版本未记录）**  
> **安装目标：Adobe Acrobat DC 20.009.20067（简体中文）**  
> **最终有效方法：微软 Program Install and Uninstall troubleshooter → 卸载 → 未列出 → 输入经过验证的 ProductCode**

## 1. 故障表现

安装 Adobe Acrobat DC 时，Windows Installer 反复要求提供旧版 `AcroPro.msi`。弹窗中的旧安装源指向 Adobe Acrobat X Pro 10.1.0 的旧目录；指定不了安装文件则无法继续。

本案例最终在 Windows 应用程序日志（来源 `MsiInstaller`）中观察到：

```text
2026-10-27 20:20:25  Event ID 11714
产品: Adobe Acrobat DC -- 错误 1714。
不能删除旧版本的 Adobe Acrobat DC。
系统错误: 1612。

2026-10-27 20:20:42  Event ID 11708
产品: Adobe Acrobat DC -- 安装操作失败。

2026-10-27 20:20:42  Event ID 1033
产品: Adobe Acrobat DC，版本: 20.009.20067
安装成功或错误状态: 1603。
```

解释：
- **1714**：无法删除旧版本产品。
- **1612**：该产品的安装源不可用。
- **1603**：安装最终失败的概括性状态，不应单独视为根本原因。

注意：事件 11714 中写的是“旧版本的 Adobe Acrobat DC”，而早期弹窗指向旧版 Acrobat X Pro。这里不假定两条信息在产品命名上完全一致，而是通过后续日志的 ProductCode 关联定位。

## 2. 排查经过

1. 系统普通卸载列表未能定位到 Acrobat X Pro。
2. 先运行较新的 Adobe Acrobat Cleaner，选 `Product to clean : Acrobat`、`Clean level : All`。工具报告已完成，却有 `Skipping older Product`，安装故障仍然存在。
3. 改用针对 Acrobat **10.x–11.x** 的旧版 Cleaner，仍然触发缺少 `AcroPro.msi` 的对话框，说明单靠清理工具并不足以排除 Windows Installer 旧源问题。
4. 微软安装与卸载修复工具的程序列表中没有目标旧版 Acrobat。
5. PowerShell 查询常规卸载项以及 Installer 的若干常见注册表位置，均没有匹配输出。**无输出并不能证明 MSI 安装记录不存在。**
6. 最后使用 Windows 应用程序事件日志，发现 `1714 + 1612`，并结合 Adobe Cleaner 的原始日志与 Installer 事务定位到同一 GUID。

关键记录：

```text
Product:              [空白]
Version:              0.000.00000
Cached MSI location:  [空白]
Install location:     [空白]
GUID: {AC76BA86-2052-0000-7760-000000000005}
```

Windows Installer 还在 2026-10-27 20:29:18 和 20:29:43 分别记录对同一 GUID 的事务开始/结束（Event ID 1040、1042）。

**本案例的 MSI ProductCode：**

```text
{AC76BA86-2052-0000-7760-000000000005}
```

它是从本机实际日志获得并交叉核对的特定产品代码。**其他设备绝不能直接照搬此 GUID 去卸载。**

## 3. 最终有效的修复操作

1. 运行微软 **Program Install and Uninstall troubleshooter**（程序安装和卸载疑难解答程序）。
2. 选择 **卸载（Uninstalling）**。
3. 目标程序不在列表中，选择 **未列出（Not Listed）**。
4. 在提示输入 **MSI ProductCode** 时，填入本案例经过日志验证的 GUID：`{AC76BA86-2052-0000-7760-000000000005}`。
5. 让向导处理损坏的旧版安装记录。
6. 用户明确反馈：**问题已修好**。

> 该反馈证实故障得到解决，但没有单独提供修复工具内部修改细节，也没有提供最终安装成功的版本截图。因此本文不臆测具体被删除的注册表键或工具内部执行步骤。

微软支持页面：[Fix problems that block programs from being installed or removed](https://support.microsoft.com/en-us/windows/deployment/install-upgrade/fix-problems-that-block-programs-from-being-installed-or-removed)。

## 4. 排障用 PowerShell 命令（只读）

### 4.1 查看最近的 Windows Installer 事件

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Application'
    ProviderName = 'MsiInstaller'
    StartTime = (Get-Date).AddDays(-1)
} -ErrorAction SilentlyContinue |
Select-Object -First 25 TimeCreated, Id, Message |
Format-List
```

重点观察 `1714`、`1612`、`1603` 及事件 `11714`、`11708`、`1033`、`1040`、`1042`。

### 4.2 查询常规卸载注册表

```powershell
$paths = @(
    'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
    'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*'
)
Get-ItemProperty $paths -ErrorAction SilentlyContinue |
Where-Object { $_.DisplayName -match 'Acrobat' } |
Select-Object DisplayName, PSChildName, UninstallString |
Format-List
```

此案例中该命令无输出，仍不妨碍通过日志找到 ProductCode。

## 5. 经验与安全边界

- 对于 `1714 + 1612`，优先考虑旧版本无法卸载、安装源失效的问题，而不是盲目更换新版安装包。
- Adobe Cleaner 报告“成功”并不代表所有旧版安装记录都已清除，尤其要留意 `Skipping older Product`。
- 可交叉使用 MSI 事件日志和官方 Cleaner 日志定位问题产品。
- **微软修复工具的“未列出 → ProductCode”路径**可以处理常规卸载列表无法显示的残留项。
- 禁止直接删除整个 `Installer\Products` 或所有 `Adobe` 注册表分支；更不可无核验地使用其他机器的 ProductCode。
- 不要随机下载同名 `AcroPro.msi` 冒充缺失的安装源。
- 不建议用 `Win32_Product` 全盘枚举：可能触发其他 MSI 产品一致性检查或修复。
- 公开案例不附带个人 Windows 用户名、具体私人目录路径、原始完整日志。
