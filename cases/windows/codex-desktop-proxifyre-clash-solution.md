# Codex Desktop 连接异常：ProxiFyre 与 Clash TLS 嗅探方案

本文仅提供脱敏后的解决方案，不包含个人设备信息、原始日志或事件时间线。适用于 Windows 下部分连接没有按预期经过代理的排查场景；不是所有连接故障的通用修复，也不是官方修复指南。

## 1. 先判断是否适用

当普通网页或显式代理请求可用，但桌面应用的远程连接、任务读取仍失败时，先比较直连与代理路径，并核对实际发起连接的程序。

只有证据指向相关连接未走预期代理，才考虑进程级接管。如果接管后仍失败，再比较 SOCKS5 本地 DNS 与代理端 DNS 的结果。仅凭 TLS 错误不能断定 DNS 污染。

修改前备份 ProxiFyre 规则和 Clash 覆写配置。本文不要求关闭 TLS 证书校验、修改应用程序文件或禁用系统安全功能。

## 2. 用 ProxiFyre 接管目标应用 TCP

在 ProxiFyre 中添加目标应用规则：

| 项目 | 设置方法 |
| --- | --- |
| 应用匹配 | 核对实际进程路径后配置；MSIX 安装可参考部分路径匹配 `\WindowsApps\OpenAI.Codex_` |
| 代理地址 | `127.0.0.1:<SOCKS5_PORT>`，占位符必须替换为本机真实 SOCKS5 监听端口 |
| 传输方式 | Plain SOCKS5 over TCP |
| 协议 | 先验证 TCP 路径 |
| 地址族 | 可先用 IPv4 做限定测试；不代表已经覆盖 IPv6 |
| 局域网绕过 | 按本机需要启用 Bypass LAN |
| 身份验证 | 与本机代理要求一致；只有代理无认证时才留空 |

注意：

- 核对目标程序实际可执行路径，不要只凭显示名称判断。
- 不要给全部同名进程或整台电脑无差别配置转发。
- 版本或安装方式变化后，路径规则可能需要调整。
- 确认后台服务实际运行及规则命中；GUI 打开或服务显示 Running 都不能替代连接验收。
- 避免将代理客户端自身加入接管规则，防止代理循环。
- 仅在可信本机回环接口使用示例地址；不要为了此方案随意开放代理端口到公网。

## 3. 必要时在 Clash 中启用 TLS SNI 嗅探及目标覆写

如果进程级转发已命中，但代理端解析域名可用、本地解析地址的路径仍失败，可进一步测试 TLS SNI 嗅探及目标覆写。

在 Clash Verge Rev 的全局扩展覆写 / Merge 中合并以下最小片段：

```yaml
sniffer:
  enable: true
  parse-pure-ip: true
  override-destination: true
  sniff:
    TLS:
      ports: [443]
      override-destination: true
```

这是局部配置，不是完整 Clash 配置文件。不同客户端或内核版本应先确认支持这些字段。

- 已有 `sniffer:` 时合并字段，不要重复定义。
- 保留其他无关设置，不用删除原有 DNS 或分流规则。
- 嗅探尝试从 TLS 握手的 SNI 获得域名，再按配置进行目标覆写；并非所有 TLS 连接都能取得可用 SNI。
- 全局覆写可能影响其他经过代理内核的 TLS 443 流量，不是只影响 Codex。
- 应用配置后检查配置是否被正确加载，再测试连接；不能以“保存成功”作为修复成功的依据。

## 4. 验证顺序

1. 检查代理本身可用，确认所填端口支持 SOCKS5。
2. 确认目标应用匹配正确且转发规则实际命中。
3. 针对同一个目标比较两种模式：
   - curl 的 `--socks5`：目标域名由本地解析。
   - curl 的 `--socks5-hostname`：将目标域名交给代理端解析。
4. 若更改嗅探设置，用同一目标、同一代理模式复测，避免把不同测试条件混为一谈。
5. 最后重复最初失败的操作，例如原生任务读取或远程连接，确认实际业务恢复。

**网络可达与业务成功应分别判断：** 无认证探测即使返回 HTTP 403，也可能只说明 TCP/TLS/HTTP 已到达响应端，不能证明登录、WebSocket 或任务读取已经正常。

无需向公开仓库上传真实目标连接日志、账号凭据或完整应用会话来证明成功。

## 5. 回滚与边界

- 若变更影响其他应用，恢复修改前的 Clash 覆写，并停用新增的 ProxiFyre 接管规则。
- 不要因为此方案效果不明，就继续叠加 TUN、环境变量和多层代理；应逐项验证。
- 自动启动属于另外的验证项。需要长期使用时，应在重启后重新检查代理、后台服务和实际业务动作。
- 本方案不能解决所有离线、未授权、账号限制或服务端故障。
- Windows Sandbox 的代理变量继承问题是不同故障，不应直接套用这份方案。

## 6. 脱敏说明

本文只保留软件通用设置、公共程序路径模式、配置示例和验证方法。代理端口使用占位符，不包含真实账号、订阅地址、私人目录、设备及任务标识、具体软件安装版本、原始日志或个人事件时间线。
